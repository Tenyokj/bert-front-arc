# Website and Product Surfaces

BERT has multiple public-facing surfaces. They serve different audiences and should not be conflated.

## Surfaces

### Marketing Site
Purpose:
- explain what BERT is
- explain why the protocol exists
- route first-time users into docs or the dApp

### Live dApp
Purpose:
- interact with live contracts
- inspect real rounds, ideas, treasury state, and profile state

### Demo dApp
Purpose:
- show the same product structure with mock data
- help first-time users, judges, or partners understand the flow without touching live state

### Docs Surface
Purpose:
- explain protocol architecture
- explain operations, upgrades, security, and constraints

## Audience Mapping

- first-time users: marketing site and demo dApp
- active participants: live dApp
- developers and auditors: docs
- judges and reviewers: dashboard, demo dApp, docs

## Product Clarity Rule

The marketing site should explain value.
The live dApp should expose live state.
The demo dApp should reduce onboarding friction.
The docs should explain protocol truth.
