# BERT Community Layer V3.2

**Status: implemented locally, unreleased, not deployed.** Version agreed on
24 October 2026. Original V3.1 Communities retain their immutable contracts.

## Changes

- Execution recipient cannot review its own milestones. Its contribution is
  excluded from review weight/count, but retains financial refund rights.
- All four Admin/Member Binary/Slate lanes require fresh Admin quorum for every
  fixed 20/40/40 transfer, including the initial 20%.
- Approval and payment must complete in seven active Community days. Expiry
  makes the whole unpaid execution budget refundable; validator rewards remain
  separate. Already paid funds are not clawed back.
- Removal/reappointment invalidates old Admin approvals through role nonces.
  Passing proof review alone neither transfers funds nor completes the plan.
- Matching new infrastructure is deployed alongside old Factories. Frontend
  URLs and graph entities preserve Factory-local Community IDs and history.

See [payment specification](V3.2-TRANCHE-QUORUM.md) and
[rollout order](V3.2-QUORUM-ROLLOUT.md). Manual dApp E2E and independent security
review remain outstanding; this is not a mainnet-readiness declaration.

## V2 remains V2.3

V2 changes in this work are NatSpec/comments in `GrantManagerUpgradeable` and
`IGrantManager`, plus documentation. Executable V2 behavior, ABI, storage layout,
payout constants and permissions are unchanged. No V2.4 or V2.3.1 is created and
no V2 implementation upgrade is required. The new Factory uses the existing
FundingPool additive allowlist, not new V2 bytecode.

## Independent version scopes

| Scope | Version | Meaning |
| --- | --- | --- |
| Global Funding Layer | V2.3, unchanged | Existing V2 economic/review rules |
| Community Layer | V3.2, unreleased | New authorization and review policy |
| Each Solidity contract | Its own `@custom:version` | Only that contract's evolution |

Manager is `2.0.0`, Hub `2.1.0`, Membership `1.1.0`, CommunityTypes `2.1.0`,
Membership/Milestone deployers `1.1.0`. Unchanged contracts keep their tags, not
`3.2.0` everywhere. A new Factory address is a new instance, not automatically
a new implementation version. New contracts start at `1.0.0`.

Whitepaper revision `1.3.0` and Console `0.1.0 Beta` have independent versions.
Keep code under `contracts/BERT/V3` and dApp routes under `/v3`: these identify
the Community Layer, not a specific minor release.

Canonical deployment commands are now `scripts/deploy/deploy-v3-2.ts` and
`scripts/deploy/configure-v3-2-funding-pool.ts` (`V3_2_FACTORY_ADDRESS`). Old
V3.1 command filenames fail closed so current bytecode cannot be mislabelled as
a historical deployment. Use a pinned historical commit to reproduce V3.1.

## Targeted pre-PR review

Two integration findings were fixed before staging: multi-transaction Community
creation now pins creator/chain/Factory/library and filters reservation logs;
the milestone indexer resets vote tallies and terminal flags for corrected proof
attempts while retaining votes during the same attempt's grace period. Four
creation tests and five mapping tests bring the frontend suite from 13 to 22.
Mapping tests execute the actual source with Graph store doubles; they are not
native Graph Node replay. Separate Graph codegen/build also passed.

See [the pre-PR review record](V3.2-PRE-PR-REVIEW.md). This targeted internal
review is not a claim that the full protocol has been independently audited.
