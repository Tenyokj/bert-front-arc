# V2.4 Release Checklist

Status: **local candidate, not deployed**. Target: a working Arc Testnet release,
not mainnet readiness or an independent-audit certificate. Updated 2026-11-24.

The contract implementation/local unit-integration stage is already prepared.
There are **six release workstreams**. The first five now have bounded local/
pinned-state, client, indexer, documentation and acceptance evidence prepared;
the public rollout workstream remains. The
client Next.js security patch is verified locally but not published; remaining
dependency risks, public upgrade approval and a fresh preflight still need review.
These are acceptance gates, not a promise of six commands or six short sessions.
A discovered blocking defect reopens the relevant gate; it does not silently
expand the release into unrelated features.

## 1. Treasury Safety and Upgrade Rehearsal - Prepared Within Documented Scope

- Preserve the populated old pool, grant/refund/bond liabilities, reserve routing
  and round-local policy semantics across the upgrade.
- Inventory and reconcile live obligations at a pinned block. Matching actual
  and recorded balances alone does not complete that inventory.
- Validate the native Arc USDC paths using a compatible execution environment;
  generic EDR's failed transfer probe is not a successful financial fork test.
- Review the source-matched Slither findings and the narrow EIP-170 size margin.
  Treat an independent audit as a separate mainnet gate, not as completed here.

Done when: evidence covers state preservation and supported asset execution,
accounting discrepancies are resolved, and no known release-blocking issue is
left unexplained. Current evidence: 268 full local tests, 55 follow-up targeted
tests, exact old live-runtime match and a bounded Arc Foundry fork upgrade with
native-USDC revenue/payout/refund and blocklist checks. Generic EDR remains
unsuitable for these native transfers. The
[pinned historical inventory](V2.4-HISTORICAL-ACCOUNTING.md) now reconciles 1,040
USDC of direct deposits plus 100 USDC of remaining bonds to actual/recorded
custody, including 200 USDC of prior bond returns. Explorer discovery was checked
against 33 canonical receipts and pinned getters; it is not an independently
exhaustive chain scan. Refresh preflight before upgrade. This is not the complete
GrantManager or browser lifecycle; those checks belong to step 5.

## 2. dApp and Console - Implemented With Bounded Verification

- Integrate candidate ABI and accounting fields with explicit reserve/revenue/
  obligations/surplus labels. Never label the pool's full balance team profit.
- Show policy delay, current and snapshotted split, fixed beneficiaries, pending
  collections and released payments. Support authorized actions and error states.
- Preserve older deployment compatibility and do not offer unsupported actions.

Done when: regression tests, typecheck/build and the relevant UI paths pass;
displayed values agree with contract reads. This is not a general redesign.

Current evidence: [client integration](V2.4-CLIENT-INTEGRATION.md), 77 frontend
tests and six Console tests, TypeScript, successful production builds, local compiled-contract
reader checks and desktop/mobile readout smoke. No wallet browser transaction
acceptance is claimed here; that belongs to step 5. The earlier Next.js 16.4.3
build blocker is resolved locally by the verified 16.4.6 patch in both clients,
without disabling the guard. Next is absent from audit; Console production-only
audit is zero. Other dApp high/moderate and Console development findings remain
open. Publication and the remaining release gates are not complete.

## 3. V2 Indexer - Implemented With Bounded Verification

- Add revenue-policy, round-snapshot, accrual, collection and beneficiary events.
- Verify replay, amounts, entity relationships and no double counting. Preserve
  existing V2/V3 history; do not redeploy V3 Factory for this V2-only change.

Done when: codegen/build/tests pass and indexed fixtures match known receipts.
Public deployment and sync verification belong to step 6.

Current evidence: [indexer integration](V2.4-INDEXER-INTEGRATION.md), ten new
mapping/manifest tests (87 root tests total), seven toolchain-security tests,
both manifest codegen/WASM builds, and deterministic duplicate-safe replay of
11 logs from compiled local-contract receipts matching final getters. Original
V2 addresses/start blocks and V3 history are retained. Step 5 subsequently adds
real Graph Node discovery/query/restart evidence, then closes clean replay/reorg
on a separate fresh MockUSDC chain. Public synchronization remains step 6.

## 4. Documentation and Release Configuration - Prepared Locally

- Update repository/site docs, relevant whitepaper sections and Obsidian while
  keeping unreleased source distinct from actual public deployments.
- Record the approved testnet terms separately from actual deployment evidence:
  20% of eligible earned fees to Treasury, with 100% of its receipts assigned to
  `0xA4B0a01dB1d68D4CDB007F78bAB63Cb4ebd814bF`. This is not 20% of pool custody.
- Preserve the owner-approved 48-hour revenue-settings delay. This application
  safety parameter is not an Arc network requirement;
  no public policy is currently scheduled and no waiting is needed to develop.
- Prepare reproducible scripts, reviewed upgrade sequence, operational recovery
  limits, release notes and exact environment-variable changes.

Done when: documentation and chosen configuration match executable behavior;
no real addresses/shares are guessed and no source candidate is called deployed.

Current evidence: [reviewed local configuration and rollout sequence](V2.4-RELEASE-CONFIGURATION.md),
five offline planner tests, three candidate site pages with four documentation
tests, the updated HTML/PDF whitepaper revision 1.4.0, dApp explanations and local
Obsidian notes. The machine configuration validates against the current manifest
and compiled artifact without RPC or signing; `readyToBroadcast` remains false.
The Treasury address is deliberately absent until an actual deployment. These
source changes have not been committed, published or activated on Arc Testnet.
Docs desktop/mobile navigation, rapid-navigation cancellation and PDF layout
were checked. The three changed website routes pass bounded desktop/mobile
smoke and the specification download works; 87 frontend tests, TypeScript and
production build pass. Core docs mirror is current. These are local checks,
not wallet/GrantManager/Graph Node acceptance or public deployment evidence.

## 5. End-to-End Acceptance - Passed Within the Bounded Local Matrix

- Exercise policy delay, a new earned-fee round, collection and beneficiary
  release, success/failure/refunds, pause behavior and older-round isolation.
- Cover the complete 20/40/40 lifecycle locally on validated execution semantics,
  plus UI/indexer agreement and V3 reserve integration regressions.
- Resolve observed bugs and record the scenario matrix and limits. External
  testers/auditors remain valuable, but are not assumed to have done this work.

Done when: the bounded matrix passes without unexplained financial differences;
contract-only tests are not presented as browser E2E.

See the [dated acceptance matrix](V2.4-E2E-ACCEPTANCE.md). Combined V3 and V2.4
Chrome tests pass (3.9 minutes), including 106 revenue-suite UI receipts and
36 event logs replayed without duplicate accounting. Core: 268 passing; frontend:
87 passing. The wallet is an injected local test provider and the asset MockUSDC.
The full native-Arc GrantManager lifecycle now passes separately: 160 receipts,
20/40/40 and cancellation after 0/20/60%, exact gas-adjusted transfers, 1.08 USDC
collected/paid. The earlier native Arc/Graph discovery/query and process restart
match 38 logs; clean replay/reorg on that fixture was blocked by its historical
`missing bytecode for code hash` RPC failure. See
[native execution evidence](V2.4-NATIVE-ACCEPTANCE.md) and the acceptance matrix.
The remaining Graph gate is now closed on a separate fresh non-fork chain:
production WASM/Graph Node 0.45.0, 169 MockUSDC fixture receipts, 38 matching logs,
restart, controlled two-block reorg and clean Postgres/IPFS replay all pass.
The earlier Arc-fork historical-bytecode failure remains a fixture limitation,
not a passing combined native-Arc/Graph test. See [Graph evidence](V2.4-GRAPH-ACCEPTANCE.md).
Stage 5 is complete within this bounded matrix; public deployment remains unauthorized.

## 6. Publish and Verify on Arc Testnet - Not Started

- Review/merge the PRs, deploy and verify the new Treasury, then perform the
  separately authorized FundingPool upgrade with revenue initially disabled.
- Deploy the indexer/client/Console changes, update actual addresses/env/receipts
  and verify existing functionality and a controlled native-USDC smoke scenario.
- Schedule the approved policy and respect its real 48-hour delay. Record what
  is actually activated, rather than declaring a scheduled policy active.
- Publish the release only with explicit verification status and unresolved-risk
  links. Follow the public full-round pilot gate in the rollout specification;
  do not claim that a local time jump completed public milestone windows.

Done when: the agreed testnet acceptance evidence, receipts, public client/index
state and docs match, with no release blocker open. Mainnet approval remains
separate. Public 48-hour and milestone review windows cannot be bypassed by
calling a local test successful; they may determine calendar completion time.
