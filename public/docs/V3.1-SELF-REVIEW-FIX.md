# V3.1 Execution-Recipient Self-Review Fix

**Subsequent agreed change:** Manager `2.0.0` retains this self-review protection
and now adds [Admin quorum for all execution tranches](V3.1-TRANCHE-QUORUM.md).
The payment-unchanged/deferred-quorum statements below describe the earlier
self-review-only patch. Neither implementation has been deployed by this work.

**Status: local source patch, not deployed.** Existing Arc Testnet Communities
retain their original immutable contracts and the documented self-review gap.
No transaction, Factory change or Community migration is performed by this patch.

## Agreed scope

Prevent the immutable `executionRecipient` from approving **or rejecting** its
own execution milestones, regardless of whether it is an ordinary Member.
Keep 20/40/40 transfers, Admin governance/withdrawal quorum and validator rewards
unchanged. An additional Admin quorum on execution tranches is explicitly deferred
until its scope, expiry and refund/liveness behavior are agreed.

## Two populations, two accounting purposes

The sealed WinnerSnapshot remains a financial record of all winning supporters.
The proposal author still cannot vote for its own proposal. An execution recipient
may support another author's proposal, but that does not entitle it to review.

| Value | Meaning in patched Manager |
| --- | --- |
| `totalSupportWeightByPlan(planId)` | Full winning-support weight, including any recipient contribution; refund denominator |
| `getPlan(planId).eligibleSupportWeight` | Full winning weight minus recipient weight; 40% review-quorum denominator |
| `eligibleReviewerCountByPlan(planId)` | Winning-supporter count minus recipient when it contributed; minimum-approver denominator |
| Snapshot `milestoneVoterWeight` / `milestoneVoterCount` | Unchanged financial weights/count; do not use directly as the patched review electorate |

Review weight/count are fixed when the sealed winner starts its plan. Both
approve and reject calls from the execution recipient revert in ordinary,
corrected and grace reviews. The weighted approval threshold stays 6,667 bps.
The minimum count stays `max(3, ceil(3% of eligible reviewers))`.

Refund eligibility is **not confiscated**: if the recipient pledged to the winner,
it can claim its original pro-rata share of unreleased capital after failure.
The refund denominator and last-claimer count include all financial supporters,
so excluding a reviewer cannot overpay others or strand the remaining reserve.
Existing financial exit locks remain until completion or the supporter's failed-
plan refund claim. Released execution tranches are not clawed back.

## Edge cases and limits

- A large recipient pledge cannot inflate review quorum or the approver floor.
- If exclusion leaves fewer than three reviewers, the plan cannot pass a milestone.
  The existing correction/failure paths remain; the floor is not silently reduced.
- An executor-only funded winner can still settle and enter the existing initial
  20% path. Its zero eligible-review weight cannot approve an empty review; the
  ordinary no-quorum grace/failure path or proof timeout makes the rest refundable.
  Rejecting settlement solely because reviewers are absent would trap vote escrow.
- Exclusion concerns the **exact recipient address**, not all people/addresses
  affiliated with it or owners of its multisig. Demo verification is not Sybil
  resistance; this patch does not establish independent human reviewers.

## Contracts and compatibility

`CommunityMilestoneManager` is patched from `1.0.1` to `1.0.2`; its stateless
`CommunityMilestoneModuleDeployer` becomes `1.0.1` because its embedded creation
code changes. Existing function selectors, plan tuple shape and events remain
compatible; new accounting getters are additive. The plan's review-weight field
now excludes the recipient. No V2 executable code, Treasury fund routing, payout
schedule or Admin-quorum policy is changed.

The frontend hides recipient review buttons even for old managers, but that is
only a UI safeguard for old instances. It checks the new accounting getters per
plan to distinguish separated accounting from unconfirmed/legacy behavior.
Subgraph financial support fields retain their meaning; synchronized ABI includes
the new getters, without claiming that the live subgraph or contracts changed.

## Regression evidence

Tests cover both milestone stages in Admin Binary, Member Binary, Admin Slate and
Member Slate; whale recipient weight; the 100-independent-reviewer / 101-total-
supporter rounding boundary; corrected and grace review attempts; fewer than three
reviewers; no independent reviewers; financial refunds with recipient first/last;
rounding dust, double claims and non-supporter rejection; and real Treasury refund
liability/exit locks. Unchanged lane tests also verify validator reward reserves.
