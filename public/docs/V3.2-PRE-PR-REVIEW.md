## Resolved findings

### P2: Creation could continue after a wallet/network switch

The reserve/deploy/activate flow previously used the currently selected wallet
and network for each new step. A switch after reservation could attempt Hub
deployment with a different creator or on a different chain, wasting gas or
leaving a partial flow. This was an integration failure, not proof of a Treasury
authorization bypass.

The UI now pins creator, chain, Factory and library at reservation. All three
receipt watchers use that chain; writes explicitly name creator and chain.
Continuation requires the original creator/network, reservation logs are filtered
to the expected Factory, and a pending reservation disables another reserve.
Switching back resumes the preserved context. Four regression tests cover these
guards, rejection cases and UI wiring; no wallet transaction was signed here.

### P2: Corrected proof inherited indexed votes from the previous attempt

The current review entity was reused without resetting yes/no weights, voter
count and terminal flags when a new proof attempt began. This could display
incorrect review totals even though contracts reset their own accounting.

On proof submission the mapping now resets attempt-scoped fields, clears old
correction/grace metadata and unsets the nullable approved flag. Correction marks
the rejected review settled. Grace for the same proof deliberately keeps votes.
Five tests exercise actual mapping source using Graph store doubles: correction,
grace, new Paid-only accounting, original V3.1 events and active-time expiry.
Native AssemblyScript codegen/build passed separately; this is not live indexing
or Graph Node replay.

## Git handoff

After fetching origin, the local Core/frontend committed trees match their
respective updated default-branch trees; docs matches its default branch too.
Create new branches from `origin/arc-usdc-migration`, `origin/arc-front-migration`
and `origin/arc-docs-migration`, preserving the existing uncommitted work.

Stage public release source, tests and docs only. In the docs repository do not
stage `.DS_Store` files. No private `.env` file, local signer key, generated graph
build directory or fabricated deployment address belongs in these PRs.

Suggested PR branches: `feat/v3-2-tranche-quorum`, `feat/v3-2-client-indexing`,
and `docs/v3-2-release`. Do not bypass the repository's PR rules.
