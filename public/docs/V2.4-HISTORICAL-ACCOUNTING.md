## Discovery and Verification

The explorer's address-log endpoint returned 49 entries and no next page, but
was **not complete**: RPC receipts contained 11 additional pool logs, including
the four bond returns and their balance updates. Do not replay that endpoint
alone as an authoritative financial history.

The inspector paginates pool address logs, USDC transfer discovery, top-level
transactions and internal transactions. It verifies 33 distinct transaction
receipts and canonical block hashes through RPC, recovering 60 pool logs and
18 USDC transfers. The ledger is replayed in transaction/log order and compared
with every recorded balance update and the pinned state. Each supported deposit
or bond movement must match an actual token transfer; direct deposits must also
match transaction calldata. Arc's native-alias Transfer log is not counted again
as a second USDC transfer.

The [machine-readable evidence](https://github.com/Tenyokj/bert-core-arc/blob/arc-usdc-migration/docs/security-reports/v2.4-historical-inventory-73753950.json)
contains receipts, discovery counts, snapshot, results and script/reducer hashes.
Explorer discovery is still a dependency: this is **not an independently
exhaustive full-chain log scan**, storage enumeration or proof about all future
states. The reconciled categories and balances have no unexplained residual at
this block. New activity or an opened round requires an updated/broader inventory.

## Reproduce

From the core root, with existing installed dependencies:

```bash
node --test scripts/local/lib/revenue-inventory.test.mjs

REVENUE_INVENTORY_RPC_URL=https://arc-testnet.drpc.org \
REVENUE_INVENTORY_BLOCK=73753950 \
node scripts/local/inspect-v2-4-historical-accounting.mjs
```

Default report: `/private/tmp/bert-v24-historical-inventory.json`. Override with
`REVENUE_INVENTORY_REPORT`. No key, wallet, signer or public transaction is used.
Missing inputs, unknown financial events, opened rounds, unmatched transfers,
missing receipts, changed implementation or mismatched state fail closed.
Do not interpret an incomplete or blocked run as permission to upgrade.

Six offline reducer tests cover receipt/index omissions, native-alias double
counting, custody mismatches, duplicate receipts, unsupported financial activity
and stale donor/bond/round state. The full Solidity suite was separately rerun:
**268 passing (44 seconds)**. Neither result is browser E2E or an independent audit.

Before an actual upgrade, repeat a fresh pinned-state preflight and handle any
new activity. This historical report does not authorize an upgrade or the
