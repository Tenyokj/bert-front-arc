See [receipt-backed evidence and remaining publication checks](V3.2.1-ARC-TESTNET-RELEASE.md).
Manager's independent contract version is `2.0.1`: a bug fix, not a new major
payment policy. Community release label: V3.2.1. V2 remains V2.3; no V2 proxy upgrade is required.

## Change

On the first rejected proof, correction opens after 48 hours and has a fixed
deadline: rejection time + cooldown + configured proof duration. Reopening does
not move this deadline. Submission at the deadline is valid; expiry is valid only
after it. An absent executor no longer prevents anyone from expiring an overdue
cooldown. Failure refunds only unpaid execution capital, preserving earlier
20%/60% payments, validator rewards and the one-correction limit.

## Interrupted Arc Deployment: Factory Proxy Only

The 25 October attempt deployed seven components at sender nonces 206..212, then
failed before proxy creation because native test USDC was insufficient. Their
addresses and verified runtime hashes are recorded separately in
`deployments/arc-testnet-v3-2-1-partial.json`; this is not an active release manifest.
This partial snapshot is incident evidence only; the canonical manifest now records
successful proxy recovery and FundingPool allowlisting of the new V3.2.1 Factory.

Do not rerun the full deployment for this incident. The narrowly scoped
`scripts/deploy/resume-v3-2-factory-proxy.ts` defaults to read-only preflight. It
checks Arc chain ID, signer, all component runtime hashes against compiled
artifacts, pending/latest sender nonce and any already-created matching proxy.
It checks estimated gas coverage before an explicitly enabled send and never
redeploys components, bumps the sender nonce or updates the FundingPool allowlist.

Recovery completed after funding the recorded deployer with faucet USDC.
For incident reproduction only, use
`V3_2_RESUME_SEND=true` with the recovery script. Only the proxy creation is sent;
its receipt is verified against implementation/admin slots and initialized
Factory references. Transaction evidence is saved in ignored
`cache/v3-2-proxy-recovery.json` and printed to the terminal. A rerun after a
successful creation verifies the existing proxy instead of sending again. If
another outgoing transaction consumed the expected nonce, recovery stops for
reassessment rather than guessing a new deployment address.
